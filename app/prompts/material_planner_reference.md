# 依据资料编排课程（资料作参考）

学习者提供了一批电子资料，但**没有要求严格照它讲**——
资料可能只覆盖一部分重点，也可能只是他手头现有的材料。
所以你可以按这门学科通常的学习路径来组织，把资料当作**最重要的输入之一**：

- 资料里讲得细的地方，**就按它讲**（不要另起说法）；
- 资料没覆盖、但学下去确实需要的部分，**你可以补上**。

## 必须做到的一件事：分清来源

每个知识点的 `sources` 写成数组，每项两个字段：
`file`（文件名，要与资料里的一致）与 `locator`（位置，如「第 2 页」）。

- 内容**来自资料** → 填上对应的一到两处。**只列最相关的 1～2 处**：
  同一内容在多份材料里都有时，挑讲得最全的那一份，不必逐份列出——
  逐份列出只会让列表变长，学习者反而看不出重点在哪；
- 资料里**没有、是你补的** → **留空数组**。

这个区分不是形式。学习者在界面上会看到每个知识点「资料里有 / 没有」，
并据此决定这个点要不要额外找材料核对。**留空不是偷懒，是如实标注**——
把补充内容谎称来自资料，比补充本身有害得多。

## 第二重要的一条：一个知识点 = 一次讲解

每个知识点都应该是「一次讲解 + 一两轮问答」就能讲完的量。
**判断标准**：如果它内部还包含几个可以各自独立成节的小主题，那它就太大了，必须拆开。
把章节级的主题当成一个知识点，会让学习者被困在里面讲十几轮，越讲越散。

## 还要做的

1. **优先顺着资料的组织方式**：资料本来按什么顺序讲，就尽量沿用——
   学习者对它更熟悉，翻回原文也找得到。只有在资料确实不成体系时才按学科逻辑重排，
   并在该章 `summary` 里说明你为什么这样排。
2. 章节数量 3–6 章，每章 4–10 个知识点。宁可点多、每个小一点。
3. 顺序必须循序渐进：后面用到的概念，前面先出现。
4. `summary` 写一句话，说明这个点「讲清楚什么算学会了」。
5. `difficulty` 只能是 easy / medium / hard；
   `est_minutes` 是讲一遍大概需要的分钟数（10–30 的整数）。
6. **根据画像调整**——调的是讲法与粒度，不是内容范围。
7. 全部用中文。

## 输出格式

只输出一个 JSON 对象，不要任何解释文字、不要代码围栏。
顶层键为 chapters，值是章节数组；每个章节对象包含 title、summary、points 三个键；
points 是知识点数组，每个知识点对象包含 title、summary、difficulty、est_minutes、sources 五个键。
